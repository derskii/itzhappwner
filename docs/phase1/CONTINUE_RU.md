# Happwner: этап 1 — исходники

Дата: 18 октября 2026 года. База: локальная версия 1.3.2-api102. APK на этом этапе не создаётся; номер релиза остаётся прежним до этапа выпуска.

## Сделано

- Целостная запись профиля: стабильный ID, название, ОС/версия/модель, клиент/версия, UA, HWID и формат генератора, имя заголовка HWID, дополнительные HTTP-заголовки, отдельные переключатели передачи полей устройства и подмены HWID через API, список точных хостов для перехватов.
- 15 встроенных вариантов: пять Happ для разных ОС, v2rayNG, Hiddify и Hiddify Xray для трёх desktop-ОС, Clash Verge Rev для трёх desktop-ОС. Для Happ явно указан пользовательский формат совместимости; его родной UA не выдумывается. Для остальных встроенных UA использованы результаты предыдущего исследования, а не версия установленного пакета по догадке.
- Сохранение и переименование своих профилей по ID. Совпадающее название другого своего профиля отклоняется. Выбор открывает редактор и не применяет запись молча. Удаление требует подтверждения; встроенные варианты копируются. Явное создание копии получает новый HWID, если он включён.
- HWID встроенного варианта генерируется один раз и сохраняется. Для UUID, HEX32 и HEX16 есть генератор; формат генератора не заменяет уже сохранённое значение без нажатия кнопки. Новый HWID создаётся с подтверждением.
- Миграция своих записей v1 с сохранением их ID и значений. Старый активный встроенный вариант переносится в свою запись с прежними полями и HWID. Старые ключи остаются для восстановления. До первого применения новой модели сохраняются прежние ручные параметры; выключение профиля восстанавливает их. Захваченный настоящий HWID не удаляется. Для уже активного старого профиля данных о состоянии ДО старого выбора нет, поэтому такая история восстановиться не может.
- Прямой запрос, Мост и новые хуки получают один снимок RequestIdentity. IPC передаёт версионированный JSON; список хостов и политика HWID обновляются атомарно вместе с идентичностью. Основные поля на главном экране при активном профиле служат отображением; редактирование открывается через общий редактор.
- Новая ссылка Моста содержит полный снимок и не зависит от дальнейшего выбора профиля. Снимок фиксируется до запроса разрешения уведомлений и переживает пересоздание Activity. Старые ссылки продолжают разбираться, без подмешивания текущей ОС из настроек. Обратный импорт новой ссылки создаёт отдельный профиль и не перезаписывает существующий ID.
- Дополнительные заголовки проверяются: ASCII, размер, HTTP token, запрет транспортных полей, ограничение количества, проверка дубликатов без учёта регистра. Предпросмотр отражает переопределения. Остальные заголовки формирует исходный HTTP-клиент; пустой UA не означает удаления его стандартного UA.
- Мост привязан к 127.0.0.1, полная строка запроса больше не пишется в лог. Неверный снимок отклоняется с HTTP 400 до обращения к подписке.

## Где продолжать

Основные файлы: DeviceProfiles.kt (хранение и каталог), RequestIdentity.kt (правила заголовков), IdentityCodec.kt (снимок), ProfileDialogs.kt (общий редактор), MainActivity.kt, SubscriptionService.kt, MainHook.kt, PrefsManager.kt, SettingsProvider.kt.

Этап 2: основной экран и каталог по готовым дизайн-концепциям, фильтры ОС/клиента, отдельный удобный редактор вместо длинного диалога, читаемый результат, сохранение черновика редактора при повороте и предупреждение об отказе от правок. Нужные для этапа 1 элементы уже доступны через кнопку профиля на главном экране и в настройках.

Этап 3: закрыть оставшиеся замечания аудита, в особенности авторизацию IPC и локального Моста, ограничения ресурсов сервера, HTTP-статусы, преобразование правил Xray и обработку ответа вне главного потока; затем собрать APK и проверить приложение/модуль на устройстве. Текущая ветка сохраняет существующий механизм IPC; этот этап не следует считать закрытием всего аудита безопасности.

Точный текущий нативный контракт Happ остаётся неизвестным: UA и имена/форматы всех полей следует подтвердить отдельно. Совместимые пресеты не обозначаются как проверенная точная эмуляция Happ. Совместимость с сервером пользователя не проверялась; его подписка и настоящий HWID в тесты и архив не включены.

## Проверки

См. CHECKS.txt. JVM-тесты проверяют модель, сериализацию, снимки и адаптер API 102. Шесть Android instrumentation-тестов для хранилища/миграции подготовлены в ProfilePersistenceTest.kt, но не запускались: они требуют Android и тестового APK. Это отдельное ограничение, а не пройденные проверки хранения на устройстве.

Обычный запуск в среде с доступными зависимостями: ./gradlew :app:testDebugUnitTest
Будущая сборка APK: ./gradlew :app:assembleDebug
Исходники не опубликованы; предыдущие незакоммиченные изменения сохранены.
