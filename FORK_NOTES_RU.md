## Профиль запроса

На главном экране кнопка «Профиль устройства» открывает готовые профили Windows 10/11, Linux, Android, iOS и macOS. Каждый профиль сохраняет постоянный HWID; свой набор ОС, версии, модели, HWID и клиента можно сохранить и удалить в редакторе. Он добавляет необязательные заголовки `x-device-os`, `x-ver-os`, `x-device-model` в запросы через Happwner и локальный мост. Пустое поле не добавляет соответствующий заголовок. Эти поля не меняют Android или системный SDK телефона. Поддержка заголовков зависит от сервера подписки.

HWID и User-Agent редактируются отдельно на основном экране. Список клиентских User-Agent расширен; полученную строку можно исправить вручную. Выбор имени клиента не преобразует формат ответа сервера в формат этого клиента. Собственный User-Agent сохраняется между запусками. Созданная ссылка моста сохраняет выбранный профиль запроса независимо от последующего переключения устройства в приложении.

В приложениях, выбранных в менеджере Xposed, профиль действует для явно перечисленных доменов подписок. Введите только имена узлов через запятую, например `sub.example.org, api.example.org`. Поддомены и шаблоны не включаются автоматически. Пустой список отключает подмену заголовков в сторонних приложениях; запросы самого Happwner и моста от него не зависят.

Перед использованием откройте в настройках Happwner раздел «Разрешённые приложения» и отметьте нужные установленные приложения. Это отдельное подтверждение доступа к профилю; приложение не может добавить себя само. Выбранные пакеты привязаны к SHA-256 отпечатку сертификата подписи, а ContentProvider сверяет фактический UID вызывающего приложения. Для Xposed также включите приложение в scope менеджера LSPosed; для LSPatch установите модуль в нужное приложение.

Хуки заголовков рассчитаны на Java URLConnection и доступный приложению OkHttp. Нативные сетевые стеки, Cronet и обфусцированные копии OkHttp могут их обходить. Перенаправления остаются под управлением HTTP-клиента и могут переносить заголовки исходного запроса; указывайте только доверенные серверы подписок. Реальную подписку и её содержимое проект не отправляет разработчикам форка.

`minSdk 26` относится к самому приложению и не гарантирует доступность современного callback API 102 на Android 8–8.1: в известной реализации Vector `onPackageReady` вызывается с API 28. В APK сохранён legacy-вход API 82, но обе ветки на устройстве не проверялись. Нативный Happ User-Agent и поддержка дополнительных полей ОС/модели публично не подтверждены; соответствующие профили помечены как совместимые шаблоны, а сервер может игнорировать их.

## Сборка и установка

Команда CI: `bash ./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug assembleRelease`. Workflow сохраняет APK в разделе Actions → Artifacts. Debug APK подписан отладочным ключом, release APK без настроенного собственного ключа остаётся неподписанным.

Идентификатор приложения сохранён: `com.happwner`. Подпись форка отличается от официальной сборки, поэтому Android обычно не разрешает установить его поверх оригинала. Сначала сохраните необходимые ссылки и настройки, затем удалите старую сборку. Поддержка хуков на реальном устройстве проверяется отдельно от успешной компиляции.

## Публикация (инструкция исходного архива)

Создайте форк [на GitHub](https://github.com/Omegaplexx/Happwner/fork), затем перенесите ветку `api102-device-profiles` или файлы из архива. Подключённый GitHub-интерфейс текущей сессии не предоставляет операцию создания форка; наличие локальных изменений не означает, что репозиторий уже опубликован.
